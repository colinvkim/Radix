**Compact browser sorting — 4 September 2026**

[FileBrowserResults.sorted](/Users/colin/Programming/Radix/Radix/Services/FileBrowserResults.swift:118) now sorts input-row indices through the existing cancellable sort. The input records remain in place, and the final result array is materialized once. Item-kind and displayed-file-count values are prepared in stationary arrays only when those sort fields are requested; other comparisons read the input records directly. No prepared-value arrays are allocated for the default size sort.

The moving elements are 8-byte integer indices on this machine, replacing wrappers containing full 168-byte file records and optional prepared values. This reduces buffer volume and record reference-management work during sorting. There is no persistent cache or additional model state. The merge algorithm, cancellation checkpoints, localized comparisons, secondary sort descriptors, name/ID fallback, and package-count rules are preserved.
