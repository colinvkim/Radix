**Chart preparation validation — 5 September 2026**

Sunburst now projects a million-child root once and retains color positions only for branches used by the layout. Treemap skips child projection when a tile has no room to display children. These changes close finding 8 of the [original audit](/Users/colin/Programming/Radix/docs/performance-audit-2026-09-04.md), leaving five of its nine findings partly or fully open. Full [measurement records](/Users/colin/Programming/Radix/docs/performance-audit/charts-results-2026-09-05.json) preserve all 26 final before/after processes.

**Changes**

Both charts share the selective color preparation previously used by Treemap. Global layouts reuse their already projected root children. Focused layouts walk to their containing global branch once and keep one lookup entry. Global branch indices and the total branch count remain unchanged, including when other branches are grouped away. Aggregate-only layouts skip color preparation entirely.

Treemap checks child-content bounds before reading a directory's children. Its squarifier also constructs weighted entries as it consumes them, eliminating a complete intermediate array. Existing grouping, container headers, segment order, and colors are preserved.

Color preparation, ancestry walks, sibling indexing, and Treemap weight/row loops now cooperate with cancellation. Sunburst checks cancellation between 256-record weight-summing batches; each batch preserves the previous arithmetic order. Treemap reuses the existing cancellable sorter. Its synchronous callback no longer requires `@Sendable`; callbacks do not escape or cross executors. Chunk sorts still have up to 16,384 elements between checks, so this does not establish a hard cancellation-latency bound.

**Targeted measurements**

The baseline uses production revision `8a0accb` with the same added benchmark and tree-read probe. Three rounds per scenario ran before and after in fresh, sequential SwiftPM Release test processes, reversing order in the second round: 18 processes. Builds did not overlap measurement. The machine was an Apple M5 MacBook Air, 10 CPU cores, 32 GiB RAM, macOS 26.6.2, and Xcode 26.6; machine load and allocator state were uncontrolled.

The fixture contains one million equal-sized synthetic files under one directory. The focused Sunburst case selects one leaf of that directory. The tiny Treemap case wraps the directory under a parent and uses a 40 × 40 layout, retaining both original and combined fixture trees. Each case emits exactly one segment. Timers cover layout only, excluding fixture construction and subsequent reflection-based fingerprints. The targeted callback is empty; task cancellation is measured separately below.

| Scenario, median | Layout before | Layout after | Projected records before → after | Peak RSS before → after |
| --- | ---: | ---: | ---: | ---: |
| Sunburst, million-child root | 323.080 ms | 117.834 ms | 2,000,000 → 1,000,000 | 1,264.1 → 988.3 MB |
| Sunburst, focused leaf | 207.180 ms | 104.439 ms | 1,000,000 → 1,000,000 | 1,096.1 → 988.4 MB |
| Treemap, tiny directory tile | 54.190 ms | 0.083 ms | 1,000,001 → 1 | 1,470.2 → 1,302.3 MB |

Flat-root Sunburst time fell 64%, with 22% lower process peak RSS. It still needs one complete child projection to group the directory. Focused Sunburst still projects the global children to preserve branch position and count, but avoids retaining a million-entry color dictionary. The tiny Treemap result comes from avoiding the million-child projection entirely; it is specific to tiles too small to show children.

Projection counts measure records returned through `FileTreeStore.children`, not filesystem/stat/resource-value calls. MB is decimal. RSS includes XCTest, synthetic fixtures, the small read probe, post-layout reflection, and allocator retention. It is neither an allocation-event count nor an isolated chart heap measurement. Record arrays share referenced strings and URLs.

**Broader layouts and cancellation**

Existing responsiveness benchmarks added eight fresh processes: one Sunburst before/after pair and three Treemap pairs. Treemap ordering reversed in the second pair. Large-scan phases and Treemap's flat phase report three-sample medians within each process; the table uses medians across processes where available. Dense-folder/root phases have one sample per process.

The broader million-node layouts were slightly slower in these samples (about 3% for Sunburst and under 1% for Treemap), while the targeted redundant work was substantially reduced. One Treemap dense-folder after sample took 21.225 ms; two follow-ups took 12.989 and 13.074 ms. All samples, including that outlier, remain in the records.

Observed Sunburst cancellation completion fell from 47.345 to 15.689 ms in the single pair. Treemap cancellation medians were 0.132 and 0.115 ms. Every cancellation probe observed cancellation before successful layout completion. Rapid root/depth changes, resizing, and navigation applied only the final request and cancelled superseded requests. These observations are not worst-case latency bounds.

All geometry, color, hit-testing, selection-overlay, keyboard-selection, and final-request fingerprints matched across variants. These are direct geometry and model probes; no interactive SwiftUI frame trace was collected. Production layouts continue to run off the main actor.
